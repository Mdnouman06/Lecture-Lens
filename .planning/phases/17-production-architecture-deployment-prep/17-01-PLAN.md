<objective>
Formalize production architecture with clear local vs hosted distinctions, standardize environment configuration without secret exposure, enforce strict exact-origin CORS controls, and verify git secret hygiene:
1. Author `docs/ARCHITECTURE_PRODUCTION.md`:
   - Clearly delineate the three deployment modes:
     - **Mode A (Local-First MVP)**: Netlify frontend (or local Vite) → user's own FastAPI `localhost:8000` → user's own `faster-whisper` + Ollama `qwen3:4b` → Supabase cloud. Netlify hosts ONLY the static React client; it does NOT host the heavy Python ML engines.
     - **Mode B (Hosted Production)**: Netlify frontend → remotely hosted backend/inference service → Supabase.
     - **Mode C (Hybrid)**: Netlify frontend → configurable `VITE_API_BASE_URL` pointing either to a user's local FastAPI server (via direct localhost or Cloudflare Tunnel) or a hosted backend → Supabase.
   - Document the critical architectural limitation: A browser visiting a public Netlify deployment cannot access `localhost` on the developer's computer. A Cloudflare Quick Tunnel bridges this for remote testing, but the local machine and tunnel process must remain continuously running.
   - Clarify the offline fallback: When the AI bridge is not running, the application gracefully provides realistic simulations and actionable setup alerts.
2. Standardize `.env.example` and `backend/.env.example`:
   - Document `VITE_API_BASE_URL` as public client configuration (not a secret).
   - Document `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` (anon key).
   - Explicitly warn NEVER to place Supabase service-role keys or private credentials into `VITE_*` variables.
   - Document `CORS_ORIGINS` as an explicit comma-separated list of exact allowed origins (e.g. `http://localhost:5173,https://your-app.netlify.app,https://your-specific-tunnel.trycloudflare.com`).
3. Harden CORS in `backend/main.py`:
   - Parse `CORS_ORIGINS` as an explicit list of exact origins without wildcard regex matchers.
   - Maintain safe local development defaults (`http://localhost:5173`, `http://127.0.0.1:5173`, `http://localhost:3000`, `http://127.0.0.1:3000`).
4. Audit repository secret hygiene:
   - Ensure `.gitignore` covers `.env`, `.env.*`, `backend/.env`, and temporary files.
   - Verify `git ls-files` tracks zero `.env` or credential files.

Purpose: Provide a hardened, secure, and clearly documented production architecture prior to static CDN deployment (`PROD-01`).
Output: Production architecture specification, clean environment templates, strict CORS allowlist, and verified git cleanliness.
</objective>

         "http://localhost:5173",
         "http://127.0.0.1:5173",
